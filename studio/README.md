# 共演 Polyphony

共演把教师已有的讲义编成可直接授课的课堂。原稿每页都有固定出处。教师可以照常翻页，也可以在某一页接入讲解、例题或学生互动。放映、作答、公布和回顾都在共演中完成。

## 一台电脑演示

解压发行包，用 Chrome 或 Edge 打开顶层的 **共演演示室.html**。首页为「讲义备课」。随包的 **示例课件/光电信号读出.pptx** 是一份普通的四页中文课件。顶层 **Polyphony-System-Architecture.pdf** 第一页是整张系统架构图，第二页列出接口和技术栈。平台内也可打开「系统架构」。

1. 导入示例。四张原页依次是 RC 电路题、解答、双端干涉题和解答。直接点「在共演开始授课」，就能用方向键或翻页笔讲完。
2. 若要演示备课，先点「获取排课建议」。第 1 页可打开 RC 理科模板，改变参数、核对解答，再将讲解采用到这页。第 3 页可将「干涉仪的两个输出端」添加到这一页。
3. 点「在共演开始授课」进入新课堂。打开投影和学生端，在同一浏览器保留三个窗口。教师翻到原稿第 3 页，点「开启本页互动」，学生提交预测和理由。教师点「返回讲义」即可从这张原页继续。
4. 结束授课后点「查看课堂回顾」。再次打开同版课件，可在「批注与课堂反馈」定位原页、查看备课记录和选用真实课堂理由。

### 在原页开一局实验

打开示例课件后直接开始授课。第 1 页的「只准测一次」和第 3 页的「画条曲线，考考机器」都可以直接启动。没有课件时，可在「学科实验」里单人试玩，再点「带入课堂」。

- **只准测一次**　学生投票选一项测量，教师点击选项才消耗全班的测量机会。每台电路随机选定一种故障。获得读数后，学生再投票判断故障，最后对照两台候选电路的预测。
- **画条曲线，考考机器**　学生可以口述或上台画目标光强。按「只给三个点，让机器拟合」锁定预测，再让全班选盲测角度。用默认双峰曲线试 180°，机器起初预测全暗，目标为全亮。把第四点交给机器后，可以看到它换了光路参数。

课堂的教师端、投影和学生端共享同一局。学生可在教师确认前改票，教师确认后公布同一条实验结果。点「返回讲义」回到开启实验的页码。独立试玩页 **Polyphony-Playlab.html** 可以直接用浏览器打开。

两项实验的电路读数与光学拟合均由本地数值模型计算。光学寻优比较两种扫描倍率与 360 个相位偏置，每组都用最小二乘计算衰减器透过率。联机版沿用下文的 Chat Completions 配置。教师点「让 AI 同桌也选一次」，模型会根据题面、已经公开的读数或三个拟合点提出一个选项和理由，建议单独显示，学生票数由真人投票决定。模型未返回有效结果时，课堂仍可继续。

### 课件和教材导入

| 输入 | 单文件演示 | 联机版 |
| --- | --- | --- |
| PowerPoint 97–2003 的 `.ppt` | 直接读二进制文档，保留可读的原页顺序、标题、正文和隐藏状态。 | 同样可读取文字。装有 LibreOffice、UNO 和 PyMuPDF 时，可附上与原页核对过的静态整页画面。 |
| `.pptx` | 按原页读取文字、表格、可读取的公式、图表数据与嵌图。隐藏页留在备课区。整页栅格图可作预览，其他页按提取内容排版。 | 可使用 LibreOffice 生成静态整页画面。页号及页数相符才采用。 |
| 教材、实验讲义 `.pdf` | 可用「粘贴一页讲义」备课。 | 由 Python 与 PyMuPDF 提取分页文字并渲染原页图。扫描件可看原页，自动排课依赖可提取的文字。 |

补充讲解、互动和课堂回顾均保留原稿页码。放映支持静态内容。原有动画、嵌入视频和宏不在支持范围；复杂版式可在备课预览中核对。服务端单次转换上限为 32 MiB、100 页，浏览器 PPTX 读取上限为 128 MiB、1,000 页，一份发布的原生讲义上限为 64 MiB。

## 多台手机加入

教师电脑安装 Node.js 22 或更高版本后，双击本目录的 **启动共演.cmd**。浏览器会打开教师工作区，保留启动窗口。macOS、Linux 或使用终端时可在本目录运行下面的命令。服务包含全部前端资源，启动过程无需安装项目依赖。

```sh
node server.mjs
```

教师电脑打开 `http://localhost:4188`。从「讲义备课」导入课件，点「在共演开始授课」创建现场课堂。「邀请学生」提供地址和二维码。学生手机与教师电脑可连接同一局域网或教师热点。若电脑有多个网卡，可在启动前用 `POLYPHONY_PUBLIC_ORIGIN` 指定可达的完整地址。教师在原浏览器、原地址重开链接，可继续管理自己的课堂。

## 赛场上可以怎么讲

上面的四页示例适合展示旧课件如何在共演内上课。下面是两轮互动的独立排练，可通过顶部课堂码创建光学样本排练，再打开「课堂控制台」。

| 操作 | 投影或评委看到什么 |
| --- | --- |
| 打开带九份样本的光学排练室，另开投影。 | 大屏上每个模拟点都标明来源。若改用现场课堂，让两位参与者独立提交选择、理由和各自相位点的光强预测。 |
| 点「公开首轮作答」，再点「整理作答证据」。 | 大屏公布选项和 A 端理论曲线。教师可以核对同选“A 端变暗”的两条原话，两人对光能去向给出的解释相反。 |
| 教师选择「追踪两个出口的能量」。 | 大屏叠加 B 端的互补曲线。学生收到针对这条分支的新问题，保留初答并可再次提交。 |
| 公布第二轮，进入「课堂回顾」。 | 在时间线上定位教学分支，查看当时引用的回答。两轮均提交者能进入配对统计。 |
| 切到「学科实验」的数字黑箱。 | 两个规则都能解释输入 0、2 的观测。让评委选一个新输入、先预测再开箱，看哪个模型与实测相符。 |

排练样本始终带模拟标记。有真实提交时，评议与参与抽签优先使用真实答卷；若想专看预设分歧，直接在初始排练室揭晓即可。抽签按提交者去重，跨轮答题仍为一人一次机会。

## 编新课和接入模型

在「AI 备课」选择参考课例，填写主题、目标与材料。生成的草稿可编辑、预览、导出为 JSON，也可在新课堂发布。

### 一分钟展示

1. 打开「AI 备课」，点「运行备课演示」。单文件 HTML 和 Node 版都能运行。
2. 给评委看编排回执。程序给干涉仪的三条观测编号。预设响应第一次引用了不存在的材料编号，校验拦截，第二次响应修正后通过。回执同时记录课谱回读、三条分支的两轮试跑和材料引用覆盖。
3. 展开分支对应的材料，打开「学生预览」。教师可以修改题目与活动，确认后点「开设新课堂」。学生作答后，由教师选择一条分支并开启第二轮。

演示响应来自内置样例。评委看到的引用校验、有限修复和课堂试跑由实际程序执行。

### 备课技术栈

| 环节 | 实现 | 展示时可查看的结果 |
| --- | --- | --- |
| 整理输入 | 浏览器原生 JavaScript 接收课题、学习目标、参考课和文本。材料按非空行编号，超过 12 段的部分保存在 M12。 | 材料编号与原文。 |
| 模型编排 | `POST /api/rooms/:code/compose` 绑定教师会话。备课和课堂评议经同一个 `lesson-provider.mjs` 适配器调用 Chat Completions。 | 结果来源、模型、输出模式、尝试次数和耗时。 |
| 检查与修复 | 结构化请求与 JavaScript 校验复用课谱字段限制，应用额外检查重复项和材料编号。输出未通过时提供具体反馈，最多修复一次。两次请求共用 9 秒。 | 失败原因、修复状态和分支引用。 |
| 课堂试跑 | `polyphony.score` v1 导出后回读。现有状态机在临时房间逐条试跑 `choice@1` 三条分支，从首答、公开、评议走到复答与关闭。 | 可读回的课谱、三条分支和试跑结果。 |
| 教师审阅 | 工坊编辑器和学生预览。教师核对材料与题意，确认后在新房间发布，草稿保存在当前浏览器。 | 备课回执与可编辑课谱。 |

模型请求超时、接口报错或修复仍未通过时，编排器返回经过独立校验和试跑的本地模板草稿。回执保留模型失败原因和本地检查结果。课谱以原有 JSON 版本交换，备课回执留在工坊草稿里。引用覆盖率表示被引用编号占全部材料编号的比例。教师审阅引用与教学任务的关联及事实准确性。

配置以下服务端环境变量并重启即可调用真实模型。备课和课堂证据筛选共用这套模型配置。 `POLYPHONY_AI_KEY` 由 Node.js 进程读取。

| 变量 | 内容 |
| --- | --- |
| `POLYPHONY_AI_BASE_URL` | 模型服务的 API 基础地址，通常以 `/v1` 结尾 |
| `POLYPHONY_AI_MODEL` | 该服务提供的模型名称 |
| `POLYPHONY_AI_KEY` | 运行服务器的进程使用的凭据 |
| `POLYPHONY_AI_OUTPUT_MODE` | `json_object`（默认）、`json_schema`（端点支持严格 Schema 时）、`text`（返回 JSON 正文的兼容端点） |

适配器向基础地址下的 `/chat/completions` 发送请求。配置状态只表示参数有效。模型和输出模式须符合具体端点的文档。备课发送主题、目标、参考课信息和编号材料。教师启用课堂评议时发送题目、候选证据编号与原文、现有分支。模型返回证据与分支编号，课堂引擎核对 ID 并还原原话。教师确认后的分支才会进入课堂事件。评议模型的调用时限为 4.5 秒，失败时沿用本地规则。

### 模块与接入点

页级排课可独立配置 `POLYPHONY_JEV_KEY`，可选 `POLYPHONY_JEV_MODEL` 默认为 `jev-latest`。教师点「获取排课建议」后，TypeSafe System One 收到页码、标题和文字摘要，可建议 RC、双端干涉、史料互证、数字黑箱或跳过。全稿先运行本地规则，最多另选 72 页调用模型。低置信度或超时的页保留本地判断。只配置 Chat Completions 时，由兼容端点返回可核对原文的页级候选。两者均未配置时，备课、授课和互动仍可使用。采用内容、翻页和开停互动由教师控制。[TypeSafe System One](https://docs.typesafe.ai/api/system-one)

| 接入点 | 源码与契约 |
| --- | --- |
| 资料解析 | `pptx-reader.mjs` 读取 Open XML，`legacy-ppt.mjs` 读取 OLE/PPT，`material-import.mjs` 组织 LibreOffice UNO 和 PyMuPDF 原页预览。教师会话通过 `POST materials/import` 上传。 |
| 页级建议 | `lecture-planner.mjs` 提供原页摘要与本地分类，`lecture-quick-provider.mjs` 接 Jev，`lesson-provider.mjs` 接 Chat Completions。教师会话使用 `POST lecture-plan`。 |
| 原生讲义 | `lecture-score.mjs` 把原页、采用的补充讲解及页上互动编成 `polyphony.lecture@1`，互动挂接 `polyphony.score@1`。通过 `POST /api/rooms` 创建课堂，`GET frame?index=…` 读取当前放映帧。 |
| 理科例题 | `teaching-science.mjs` 负责 RC 暂态和理想等分双端干涉的数值计算与校验。界面把同一组参数生成的题面、解答和曲线接回原页。 |
| 批注复用 | `material-notebook.mjs` 在教师浏览器用 IndexedDB 按文件内容摘要、页码保存批注、草稿、采用记录及核对过的学生原话。相同内容可复用，同名改版独立保存。 |
| 应用与角色 | `dist/app.mjs` 挂接工坊、指挥台、学生端、投影、实验室、回放和架构页。 `dist/views` 负责界面。 |
| AI 备课 | `dist/core/lesson-composer.mjs` 封装材料、计划约束、校验与试跑。 `lesson-provider.mjs` 封装协议、输出模式和请求时限。 |
| 活动接口 | `dist/core/activities.mjs` 以 `activityId` 绑定活动版本，声明 `scene`、`input`、`aggregate`、`reveal`。现有活动包括干涉相位扫描、史料互证、数字黑箱和通用选择理由。AI 草稿生成通用 `choice@1`。 |
| 课谱接口 | `dist/core/score-package.mjs` 定义可交换的 `polyphony.score` v1 JSON，含课谱、分支、学生复答题及活动版本。 |
| 课堂互动 | `dist/core/engine.mjs` 应用命令、校验轮次和阶段并记录事件。学生提交 `join`、`respond`，教师使用 `reveal`、`analyze`、`branch`、`revise`、`close`、`draw` 等命令。 |
| 联机连接 | `server.mjs` 提供 `GET /api/status`、`POST /api/rooms` 和班级子路由 `POST session`、`POST compose`、`POST commands`、`GET events?role=…`。 `dist/core/transport.mjs` 为 HTTP 与浏览器排练暴露统一会话接口。 |
| 数据与回放 | 联机房间由 Node 文件快照持久化，离线房间由浏览器持久化。回放用事件和作答编号追溯教学决定。 |

### 开源复用与架构取舍

- 内容契约借鉴 H5P 的语义定义。同一份计划约束用于模型编排和本地校验，再接上项目已有的课谱导入导出与课堂状态机。[H5P semantics](https://h5p.org/semantics)
- 模型层借鉴 Vercel AI SDK 的兼容端点与能力声明，将接口差异限制在适配器。运行时继续使用 Node 原生 `fetch`，单文件演示可离线跑完整流程。[AI SDK OpenAI Compatible Providers](https://ai-sdk.dev/providers/openai-compatible-providers)
- 备课采用阶段校验与有限修复。校验失败能在本地模板和试跑回执中复现，教师可在赛场展示具体失败原因。[Anthropic workflows](https://www.anthropic.com/research/building-effective-agents)
- 多端互动沿用 HTTP 命令和 SSE 角色快照。重连时发送最新版本状态，与现有事件回放分工。现场邀请的二维码继续复用 MIT 许可的 QR Code Generator。[MDN SSE](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events) · [QR Code Generator](https://github.com/kazuhikoarase/qrcode-generator)

## 运行与数据

- `dist/core` 保存课谱、状态机、光学模型和角色视图。`dist/views` 保存课堂指挥台、学生端、大屏、工坊、实验室和回放。
- 教师命令通过 HTTP 提交，服务器用 SSE 向各端推送当前角色的快照。学生可看自己的初答和改答，投影读取匿名样本及聚合结果。新轮次会拒绝上轮延迟到达的页面操作。
- 联机版随当前页面加载视图和样式，打开邀请时再加载二维码组件。支持 gzip 的浏览器会收到压缩后的常用静态资源，再次打开时可用 ETag 校验缓存。单文件演示仍可断网打开。
- Node 将课堂状态写入 `.polyphony-rooms.json`，发布的讲义另存于同名路径加 `.lectures/` 的目录。可通过 `POLYPHONY_ROOM_FILE` 指定位置。离线版将已发布课件放在 IndexedDB，小型课堂状态在同一浏览器各窗口同步。私人批注保存在教师的备课浏览器。投影和学生端只接收当前放映帧及各自角色的数据。
- 房间快照沿用原有 JSON 格式，每次提交只重新编码发生变化的房间，再原子替换快照文件。完整文件的写盘量仍随历史房间总大小增长。课堂服务会复用当前放映帧的编码，并在最后一个 SSE 客户端断开后停止心跳。
- 若要启用静态整页渲染，安装 LibreOffice Impress、可导入 `uno` 的 Python，以及可导入 `pymupdf` 或 `fitz` 的 Python。可用 `POLYPHONY_SOFFICE`、`POLYPHONY_LIBREOFFICE_PYTHON`、`POLYPHONY_PDF_PYTHON` 分别指定程序。随附 Dockerfile 已列出这些依赖。[LibreOffice UNO](https://api.libreoffice.org/) · [PyMuPDF](https://pymupdf.readthedocs.io/)
- 可在有持久化目录的单实例 Node 主机上部署，绑定 `HOST` 和 `PORT`。随附的 Dockerfile 监听 4188，数据目录为 `/data`。外部反向代理需允许 SSE 长连接。
- 在本目录执行 `node --test` 可运行内置回归测试。执行 `node tools/export-offline.mjs` 可由当前资源重新生成上一级目录的单文件演示。
